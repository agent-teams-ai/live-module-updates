## Evidence classes and counting

Use these labels when adding a finding:

1. **Accepted owner contract:** an applicable ADR/profile says what must hold.
2. **Inspected source:** identified code or upstream documentation expresses a
   mechanism; no native execution follows merely from reading it.
3. **Model or local witness:** stated assumptions and observed controls for the
   exact finite/file/database model; no extrapolated failure probability.
4. **Native mechanism experiment:** actual supported installed inputs and raw
   positive/negative results, limited to the tested mechanism.
5. **Representative integrated fixture:** actual package/runtime mechanisms,
   independently specified outcomes and concrete reset/negative controls.
6. **Independent test-Host qualification:** the same built behavior in
   independently wired Hosts for a named envelope; two configurations or two
   shared-core adapters are not independent public SPI implementations.
7. **Public delivery / production adoption:** the package or product owner
   accepts its separately applicable release, conformance and integration gates.
   Executable test packages do not establish either fact.

Keep case counts separate from assertions, repeated executions, platform rows
and total jobs. A skipped or queued row is not a successful execution. Preserve
the original failure beside the corrected attempt and state which claim changed.

Examples that must not be overstated:

- The ordering model measured admission refusal in finite schedules; it did not
  prove native stale execution or a failure probability.
- Zero active calls does not establish that streams, debt, history or old-client
  artifact holds ended. The 128 hold combinations are a model, not a leak rate.
- Same package bytes do not imply the same local opaque identity or semantic
  state revision. Borrowing a reference does not qualify arbitrary graph reuse.
- A repeated close can return before an original finalizer. Waiting abandonment
  does not establish physical completion.
- The corrected cross-tier acknowledgement witness is application-level
  uncertainty. Its preserved first failure must not be relabelled as a passed
  TCP-reset or transport-recovery experiment.

## When another experiment is justified

Name the open choice, owner, exact supported inputs and rejecting outcome first.
Prefer a representative test Host with a materially different contract or
runtime boundary over another equivalent toy router. Applications need not
exist first. Reuse known positive/negative controls and vary the actual disputed
mechanism. Preserve an
independent expected result, full failure output and provenance. Update the
current decision or profile when evidence changes it; do not count a longer
research document as a closed implementation decision.

Priority is the real static foundation and packed headless integration, then
qualified public operation admission, actual state/receiver transactions and
the selected UI/runtime boundary. The proposed S1–S7 campaigns retain their
full scope; partial evidence for a mechanism does not close an entire campaign.
